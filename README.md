PropertyBoss watches public real-estate listings, estimates how far a price sits from the local market, and scores how likely a listing is to leave the market.

## Features

- Scan of Czech listing sites that have a connector (Bazos, UlovDomov, Bezrealitky)
- Markets configured for Czechia, Italy, and the Netherlands
- Hedonic market-price model
- Liquidity model: probability of leaving the market, not of a completed sale
- Delisting detection with a guard on sudden mass disappearance
- Optional Telegram notifications
- Local dashboard (list, map, object, zones, models) in Russian and English
- ECB reference rates; money is stored as integers in minor units
- Optional translation and attribute extraction through an OpenAI-compatible API

## Requirements

- Go 1.25 or newer
- PostgreSQL 16 with PostGIS
- Node.js 20 or newer, and npm, to build the dashboard
- Network access to the listing sites and to the ECB rate feed when those jobs run

A laptop CPU is enough. The project does not need a GPU. Disk use grows with the database and, when photo download is enabled, with the local cache in `data/photos` (that directory is not in git).

## Quick start

```sh
git clone https://github.com/alexolvin/PropertyBoss.git
cd PropertyBoss
cp config/config.example.yaml config/config.yaml
cp config/secrets.example.yaml config/secrets.yaml
# Edit config/secrets.yaml and set database.dsn.
# Leave tokens empty until you need Telegram or an LLM.

go run ./cmd/pb migrate
go run ./cmd/pb fx sync

cd web && npm ci && npm run build && cd ..
go run ./cmd/pb serve
```

The API and the dashboard share `dashboard.listen` (default `http://127.0.0.1:8090`). The API has no authentication. Do not bind a public interface.

## Configuration

Copy the example files. `config/config.yaml` and `config/secrets.yaml` are listed in `.gitignore`.

| Name | Purpose | Example | Required |
|---|---|---|---|
| `database.dsn` | PostgreSQL connection string. Store it only in `config/secrets.yaml`. | `postgres://propertyboss:CHANGE_ME@127.0.0.1:5432/propertyboss?sslmode=disable` | yes |
| `dashboard.listen` | Bind address for the API and the UI | `127.0.0.1:8090` | yes |
| `dashboard.ui` | Directory of the built frontend | `web/dist` | no; empty serves JSON only |
| `PB_CONFIG` | Alternate path to the YAML config | `config/config.yaml` | no |
| `telegram.token` | Bot token, in `config/secrets.yaml` | empty | no |
| `telegram.chat_id` | Operator chat id, in `config.yaml` | empty | no |
| `translate.api_key` | LLM key for translations, in `config/secrets.yaml` | empty | no |
| `extract.api_key` | LLM key for attribute extraction, in `config/secrets.yaml` | empty | no |

Valuation, liquidity, delisting, and schedule thresholds are in `config/config.example.yaml`.

## Usage

```sh
go run ./cmd/pb scan -list
go run ./cmd/pb serve
go run ./cmd/pb notify status
go run ./cmd/pb doctor web
```

`pb doctor web` checks that `web/dist` matches the git tree. `make ui` rebuilds the UI, starts a one-shot server on `127.0.0.1:8091`, and runs the Playwright suite. That target needs `config/config.yaml`, `config/secrets.yaml`, and a reachable database.

Zone polygons are imported with `pb zones import` from a GeoJSON file you supply. Those files stay outside git (`data/` is ignored).

Listing photographs are kept for the operator's own use. This repository does not grant a license to redistribute them.

Probe captures under `artifacts/` stay on the machine that ran the probe. They are gitignored because they record the machine and samples of third-party pages. `pb sources report` writes `docs/sources/CZ_REGISTRY.md` and does not record the machine name.

## Testing

```sh
go test ./...
```

Tests that need PostgreSQL skip themselves unless `PB_TEST_DSN` names a disposable database.

Dashboard tests, with the API already listening:

```sh
cd web && npm ci && npx playwright install chromium
PB_UI_BASE_URL=http://127.0.0.1:8090 npm run test:ui
```

# Отчёт по этапу 1 — каркас, миграции, PostgreSQL+PostGIS, курсы ЕЦБ (ТЗ §15.1)

Дата: 2026-08-26. Хост: `vzu5-claw`. Исполнитель: Claude (Claude Code).
Критерий готовности этапа: «Курсы грузятся, деньги хранятся целыми, тест на
отсутствие float в денежном пути проходит».

## Реализовано

- **PostgreSQL 16.15 + PostGIS** (кластер `16/main`, порт 5432). Роль
  `propertyboss` + БД `propertyboss`; DSN в `config/config.yaml`
  (в `.gitignore`, в репозиторий не коммитится). Расширение `postgis`
  создано суперпользователем до миграций (роль приложения не суперпользователь;
  `IF NOT EXISTS` в миграции — no-op без привилегий).
- **16 миграций** (`0001…0016`), схема ТЗ §12: currencies, fx_rates +
  функция `fx_rate_for()`, zones, zone_reference_prices, attribute_registry,
  sources, objects, object_translations, valuations, liquidity_estimates,
  scan_runs, raw_listings, object_links, price_history, search_configs,
  scan_windows/scan_yield, phone_tasks/notifications, schema_migrations.
  Раннер идемпотентен (проверка по `schema_migrations`), все 16 применены
  на чистой БД.
- **Справочник валют**: EUR, CZK; экспоненты из ISO 4217 (=2 для обоих),
  берутся из БД, не из кода.
- **Загрузка курсов ЕЦБ** (`pb fx sync`) — два канала, оба пишут в `fx_rates`
  с явной построчной атрибуцией (`fx_rates.source`, ТЗ §13):
  1. официальный XML-фид `eurofxref-daily.xml` (последний опубликованный день)
     — source `"ECB eurofxref daily XML"`;
  2. зеркальный API `frankfurter.dev` для окна `backfill_days` (те же
     референсные курсы ЕЦБ) — source `"ECB eurofxref via frankfurter.dev"`.
  Ошибка одного канала — явное «ВНИМАНИЕ» в логе (ТЗ §0.4); ошибка обоих —
  ошибка запуска. Официальный фид перезаписывает зеркало на день публикации.
- **Результат загрузки**: 23 рабочих дня окна 2026-07-24…2026-08-25
  (CZK, base EUR). Выходные в фиде отсутствуют — не подставляются (ТЗ §5).
- **Деньги**: суммы — `BIGINT` минорные единицы + `currency CHAR(3)`;
  курсы — `NUMERIC(20,10)`, записываются в БД строкой (NUMERIC разбирается
  точно, без float). JSON API отдаёт суммы целыми.
- **Тест «нет float в денежном пути» — проходит.** Реализация точная, по AST
  (`internal/money/money_test.go`): пакеты `internal/money` и `internal/fx`
  не содержат идентификаторов `float32`/`float64`, селектора `big.Float`
  и импорта `"math"` (`math/big` разрешён — точная рациональная арифметика).
  Конвертация — `math/big.Rat`, округление half-away-from-zero.

## Допущения

- `fx.backfill_days = 30` (в конфиге, не в коде) — покрывает первое окно
  накопления наблюдений; значение можно менять без правки кода.
- **Эндпоинты ЕЦБ с сети `vzu5-claw` игнорируют параметры `from`/`to`/`date`**
  (проверено 2026-08-25 `curl`-запросами: `daily`-фид отдаёт только последний
  день при любом `from`/`to`; SDMX REST API `data-api.ecb.europa.eu`
  дополнительно блокируется WAF). Поэтому окно за 30 дней загружается через
  зеркало `frankfurter.dev` (публичный доступ к тем же референсным курсам ЕЦБ,
  без ключа). Атрибуция каждой строки — в `fx_rates.source`; данные того же
  источника (ЕЦБ), канал доставки другой.
- Справочник валют на старте содержит только EUR/CZK (целевые рынки, ТЗ §1);
  расширение = строка в справочнике, код не меняется.

## Заглушки

- Нет. Все функции этапа работают с реальной БД и реальными внешними
  эндпоинтами; `ErrNotImplemented` на этом этапе не используется.

## Требует ручной проверки

- **Совпадение значений зеркала и официального фида** проверено на одной дате
  (2026-08-25: CZK 24.099 в обоих каналах — совпадает). Систематическую
  сверку (по всем датам окна) не проводил — рекомендую разовую ручную проверку
  или периодическую задачу.
- Пароль БД сгенерирован случайно и записан только в `config/config.yaml`;
  его не стоит копировать в другие системы.
- Ручная проверка `pb migrate` повторно: «новых миграций нет» (проверено,
  идемпотентно).

# Отчёт по этапу 2 — дашборд v1: search_configs, i18n ru/en, валюта отображения (ТЗ §15.2)

Дата: 2026-08-26. Хост: `vzu5-claw`. Исполнитель: Claude (Claude Code).
Критерий готовности этапа: «Настройка страны и фильтров без правки кода».

## Реализовано

- **REST API** (`pb serve`, слушает `dashboard.listen` = 127.0.0.1:8090):
  - `GET /api/health`, `GET /api/meta` (страны, валюты с экспонентами из
    справочника, типы сделок, валюта рынка, дата последнего курса);
  - `GET /api/sources`, `GET /api/attribute-registry`;
  - `GET /api/search-configs` (с фильтрами `country`, `source_id`),
    `GET /api/search-configs/{id}`, `POST /api/search-configs`,
    `PUT /api/search-configs/{id}` (полная замена),
    `DELETE /api/search-configs/{id}` (мягкое: `active=false`);
  - `GET /api/objects` (фильтры `country`, `status`, пагинация),
    `GET /api/objects/{id}`.
- **search_configs**: страна и тип сделки — из конфига
  (`dashboard.countries`, `dashboard.deal_types`); цена — целые минорные
  единицы в JSON (без float, ТЗ §5); площади — строки (`NUMERIC`);
  валюта = рыночная валюта страны (`dashboard.market_currencies`);
  фильтры атрибутов **валидируются по `attribute_registry`** (ТЗ §6):
  неизвестный ключ — 400 с причиной, значение проверяется по типу
  (bool/enum/int/float) и `allowed_values`.
- **Отображение валюты** (ТЗ §5): цена объекта в рыночной валюте +
  опциональная цена в выбранной пользователем `display_currency`;
  конвертация — `fx_rate_for()` по курсу на дату наблюдения объекта
  (`last_seen_at`), не по «сегодняшнему»; результат помечен производным
  (`derived`), при подстановке последнего известного курса — `rate_stale`.
  Отсутствие курса — объект показывается без конвертированной цены,
  подстановка молчаливо не происходит.
- **Дашборд** (React 19 + Vite 6 + TS strict, `web/`):
  - вкладки «Конфигурации поиска» / «Объекты»;
  - i18n `ru`/`en` (i18next, JSON-каталоги, переключатель в шапке,
    сохраняется в localStorage);
  - выбор валюты отображения (из справочника, localStorage);
  - форма создания/редактирования конфигурации: страна, тип сделки, тип
    объекта, диапазон цены (в major-единицах, преобразование в минорные —
    строковое, без float), диапазон площади, чекбоксы/селекты/числовые
    поля фильтров генерируются из `attribute_registry` по `data_type`;
  - таблица объектов: цена в рыночной и в отображаемой валюте
    (с пометкой staleness), статус с причиной, пагинация.
- **Критерий этапа «настройка страны и фильтров без правки кода» —
  проверен**:
  - страны/типы сделок/валюты — в `config/config.yaml` (секция `dashboard`);
  - фильтры — данные в `attribute_registry` (реестр в БД, не в коде, ТЗ §6);
  - сквозной smoke-тест по HTTP: создание → чтение → полная замена →
    деактивация → 404; валидация: 400 на одну цену-границу, 400 на
    неизвестную страну, 400 на фильтр, отсутствующий в реестре;
  - фронтенд: `tsc --noEmit` без ошибок, `vite build` собран, full-stack
    проверка через Vite-прокси (`/api` → backend) — health/meta отвечают.

## Не реализовано и почему

- **Данные в `objects` отсутствуют** — коннекторов ещё нет (этап 3);
  вкладка «Объекты» пуста до первого скана. Это отсутствие данных,
  а не заглушка.
- **`attribute_registry` пуст** — наполняется на этапе 3 с
  `source_evidence` по факту разбора конкретных агрегаторов (ТЗ §6:
  «не по памяти»). До этого фильтры атрибутов в форме не отображаются.
- **Список источников пуст** — подбор источников в рантайме (ТЗ §15.10),
  проверка `access_policy` — этап 3 (ТЗ §13).

## Допущения

- API слушает **8090**, а не 8080: порт 8080 на `vzu5-claw` занят другим
  сервисом (рабочая область второго агента, проверено 2026-08-25).
  Значение в `dashboard.listen` конфига — меняется без правки кода.
- `PUT /api/search-configs/{id}` — **полная замена** конфигурации
  (предсказуемее частичного патча; форма всегда шлёт все поля).
- `DELETE` — **мягкое удаление** (`active=false`): история сканов
  (`scan_runs`) ссылается на конфигурацию, жёсткое удаление разрывало бы
  ссылки.
- Язык и валюта отображения хранятся в localStorage браузера
  (на пользователя, а не на аккаунт — аутентификации в системе нет,
  дашборд только на локальном хосте).

## Заглушки

- Нет. Все эндпоинты — рабочие, против реальной БД. Пути ошибок — явные
  400/404/500 с машиночитаемым сообщением; `ErrNotImplemented` на этом
  этапе не используется.

## Требует ручной проверки

- **Визуальная проверка UI в браузере** (формы, переключение языка и
  валюты, таблица, пагинация) — проверено на уровне API и сборкой
  (типы + production-бандл), но не кликами. Dev-режим:
  `npm run dev` (web/) или `npx vite preview` — прокси на 8090.
- Создание первой реальной конфигурации поиска через UI после наполнения
  реестра атрибутов (этап 3).
- Порт 8090 зафиксирован в `web/vite.config.ts` (dev-прокси) — при смене
  `dashboard.listen` прокси надо менять синхронно (dev-конфигурация,
  не продакшен-путь).

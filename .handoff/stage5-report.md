# Отчёт этапа 5 — Гедоническая модель + правила отказа (ТЗ §7.2–7.3)

Дата: 2026-08-28. Команда: `pb valuate` прогнана на реальных данных (см. «Результаты на реальных данных»).

## Реализовано

### 1. Гедоническая модель (ТЗ §7.2)

`internal/valuation/model.go` — `Fit(*ModelInput) (*FitResult, error)`:

- Модель **отдельно для каждой страны × типа сделки** — объединённых моделей нет (ТЗ §7.2).
- Зависимая переменная: `log(price/area)` (цена в минорных единицах, цена за м²).
- Матрица факторов: интерцепт + дамми по зонам (в выборке) + one-hot по атрибутам из
  `attribute_registry` (`used_in_pricing=true`, страна; bool → "false"/"true", enum → allowed_values,
  int/float → числовой столбец) + `log(area)` + 11 месячных дамми (январь — базовый).
- Ридж-регрессия: `beta = (XᵀX + λP)⁻¹Xᵀy`, `P = diag(0,1,…,1)` (интерцепт не штрафуется).
  λ выбран из сетки k-fold кросс-валидацией (округлое распределение фолдов по id объекта,
  строго «меньше MSE побеждает», детерминированно).
- 95% интервал предсказания для нового объекта:
  `ŷ ± t(0.975, n−K)·σ·sqrt(1 + xᵀ(XᵀX+λP)⁻¹x)` — интервал шире доверительного для среднего,
  как и положено предсказательному.
- Матричная алгебра — gonum/mat (v0.17.0 из локального модульного кеша).

`internal/valuation/tquantile.go` — квантиль t-распределения Стьюдента. В локальном кеше
gonum **нет пакета stat/dist** (особенность окружения, см. ниже), поэтому CDF считается
численно: адаптивное правило Симпсона по гладкой плотности t (критерий 15·tol, поправка
Ричардсона 1/15, глубина ≤ 40, abs tol 1e-13) + бисекция (100 итераций, удвоение верхней
границы). Проверено: табличные квантили df=1…1000 с точностью 1e-4, предел Коши при df=1,
симметрия/монотонность CDF (тесты).

### 2. Правила отказа (ТЗ §7.3)

Все три правила, каждое возвращает **NULL + причину, а не число**:

1. `n < min_obs_per_param × K` → отказ `insufficient_observations: n=… < …`; при n=0 —
   `no_observations`.
2. Зона с `< min_obs_per_zone` наблюдений → эффект ближайшего родителя с достаточной
   выборкой, строка помечается `zone_fallback=true`.
3. Доля пропусков по ключевому ценовому атрибуту > `max_missing_rate` → отказ
   `attribute_missing_rate: attr=… rate=…`.

При отклонённой модели в `valuations` записывается по строке на **каждый** активный объект —
`price_deviation=NULL`, `deviation_null_reason` = причина отказа (для объектов, не прошедших
в выборку, — своя причина, см. ниже).

### 3. Причины NULL на уровне объекта

Выборка — объекты с ценой и площадью в валюте рынка. Исключённые получают честную причину
(порядок проверок важен: цена — зависимая переменная, она первична):

| Причина | Условие |
|---|---|
| `no_price` | цена NULL или ≤ 0 |
| `no_currency` | валюта NULL (столбец `objects.currency` nullable) |
| `currency_mismatch` | валюта есть, но не рыночная |
| `no_area` | площадь NULL или ≤ 0 |

### 4. Прогон и хранение

- `internal/valuation/run.go` — `Run(ctx, pool, cfg, country, dealType)`: активные объекты,
  реестр атрибутов, родители зон → выборка → `Fit` → строки `valuations` (пачками по 100,
  один tx на (страну, тип сделки)).
- `migrations/0013_valuations.sql` — таблица `valuations`: `model_version`, `price_deviation`,
  `deviation_null_reason`, `predicted_price_minor`, `interval_low/high_minor`, `sample_size`,
  `r_squared`, `zone_fallback`, `computed_at`; индекс `(object_id, computed_at DESC)`.
  Таблица историческая: повторный прогон **добавляет** новые строки (без unique на object_id);
  читается только последняя (см. «Предположения»).
- `cmd/pb/valuate.go` — `pb valuate [-country XX] [-deal-type T]`; по умолчанию все страны из
  `dashboard.countries` × все `dashboard.deal_types`. В журнал — либо параметры построенной
  модели (n, params, λ, R², оценено/null/записано), либо «модель ОТКЛОНЕНА (ТЗ §7.3)» с причиной.
- Конфиг: блок `valuation:` — `min_obs_per_param: 10`, `min_obs_per_zone: 30`,
  `max_missing_rate: 0.5`, `kfold: 5`, `lambda_grid: [0.01, 0.1, 1, 10, 100]`.

### 5. Дашборд

- `GET /api/objects` — у каждого объекта поле `valuation` (последняя строка `valuations` через
  `LEFT JOIN LATERAL … ORDER BY computed_at DESC, id DESC LIMIT 1`).
- `web/src/components/ObjectsView.tsx` — колонка «Оценка (модель)»: **число показывается

  модели, n, R²; зона с fallback помечена.

## Результаты на реальных данных (2026-08-28, `pb valuate`)

| Комбинация | Активных объектов | В выборке | Модель | Строк в valuations |
|---|---|---|---|---|
| CZ/sale | 7762 | 0 | ОТКЛОНЕНА: `no_observations` | 7762 (no_area=7087, no_price=675) |
| CZ/rent | 0 | 0 | ОТКЛОНЕНА: `no_observations` | 0 |
| IT/sale, IT/rent, NL/sale, NL/rent | 0 | 0 | ОТКЛОНЕНА: `no_observations` | 0 |

Сверка в БД: `total=7762, with_deviation=0, NULL без причины=0` — критерий этапа 5
(«NULL с причиной, а не число») выполнен.

**Почему CZ/sale честно отклонена**: у всех 7762 объектов базос `area_sqm=NULL` — площадка
публикует площадь только в свободном тексте, структурированной площади в коннекторе нет.
Выборка (цена + площадь) пуста → `no_observations`. Модель не выдумала число — именно это
требуется ТЗ §7.3 при недостатке данных.

**Обнаруженная в прогоне ошибка данных**: 675 объектов имеют `currency=NULL`
(столбец nullable). Первый прогон падал: скан в `string` → «cannot scan NULL into *string».
Исправлено: скан в `*string`, новая причина `no_currency` (+ i18n ru/en), порядок проверок
цена→валюта→площадь, регрессионный объект в `TestRunLiveFull`. Эти же 675 объектов не имеют
цены, поэтому в итоговом разборе они подписаны `no_price` (первичная причина).

## Не реализовано и почему

- **Планировщик прогона модели** — этап 5 ТЗ требует модель и правила, а не расписание;
  cron/адаптивное расписание — этапы 8/11. Сейчас `pb valuate` запускается вручную.
- **Извлечение площади из свободного текста** — единственный путь сделать CZ/sale
  выборочным (сейчас 0/7762 с площадью). Это отдельная задача по обработке текста
  (кандидат — этап 10/свой этап), за рамками этапа 5.
- **Модели по зонам** (отдельная регрессия в каждой зоне) — ТЗ §7.2 задаёт одну модель на
  страну × тип сделки с зонами как факторами; пер-зонные модели при текущем объёме данных
  перифитили бы и противоречат ТЗ.

## Допущения

- Месяц — из `last_seen_at` (UTC), 11 дамми, январь базовый. Дата размещения площадки
  ненадёжна (§14.5.1), последняя дата наблюдения — лучший доступный прокси времени.
- Интерцепт не штрафуется (P = diag(0,1,…,1)); при λ>0 матрица (XᵀX+λP) положительно
  определена — Solve не может дать сингулярность.
- `model_version = "hedonic-ridge-v1"` — человекочитаемый ярлык версии, не хэш параметров.
- Повторный `pb valuate` добавляет строки истории; API отдаёт только последнюю на объект
  (LATERAL + LIMIT 1). Очистка истории — не предусмотрена (таблица небольшая).
- Валюта объекта, отличная от рыночной, не конвертируется в модель (курс есть, но ТЗ §7.2
  строит модель в валюте рынка; конвертация выборок разных валют — не задача этапа 5).

## Особенности окружения (важно для этапов 12–13 — перенос на vzu5-omi)

Локальный модульный кеш содержит **изменённый gonum v0.17.0**:

1. `stat/dist` отсутствует полностью (нет StudentT/TCDF) → `tquantile.go` считает квантиль
   численно (Симпсон + бисекция). При переносе с «родным» gonum можно заменить на
   `dist.StudentT`, но текущая реализация самодостаточна и покрыта тестами — менять не нужно.
2. `mat.Dense.Copy` **сломан**: копирует только пересечение размерностей получателя и
   источника и **не realloc-ит получателя** — `new(mat.Dense).Copy(m)` остаётся 0×0 (в
   «родном» gonum Copy realloc-ит через reuseAs). Использовать `mat.DenseCopyOf`
   (внутри — корректный `CloneFrom`) или `Mul` в новый приёмник (он realloc-ит).
   Зафиксировано комментарием в `model.go`.
3. В `mat` нет `AddElem`, `NewIdentity`, `RawRowViewer` — заменены ручными циклами
   (`identityDense`, явные срезы в `NewDense`, `RawRowView`).
4. Поля `blas64.General` экспортированы (Rows/Cols/Data/Stride) — используется в `sseOf`.
5. `math.Lgamma` возвращает два значения (logΓ и знак) — вторым можно пренебречь на
   положительных аргументах.

Прочее:

6. gofmt этого тулчейна (go1.25.13) имеет другой алгоритм выравнивания, чем gofmt,
   форматировавший файлы ранних этапов: 8 старых файлов (config.go, bazos.go, bazos_test.go,
   frankfurter.go, loader.go, money_test.go, listing.go, scan_test.go) числятся
   «неотформатированными». Они **не переформатированы** (шум в диффе); новые файлы этапа 5
   отформатированы текущим gofmt.
7. Go: строка, заканчивающаяся строковым литералом, получает неявный точка-запятую —
   закрывающую скобку нельзя ставить на следующей строке после строки (встречалось в тестах).

## Файлы агента — только `.a/`

Все файлы, касающиеся работы кодового агента, находятся в каталоге `.a/` (локально; каталог в `.gitignore`, в публичный репозиторий не попадает).

1. **Задания** (ТЗ, задачи, постановки работ) — только `.a/tasks/`.
2. **Handoff** (передача контекста между сессиями/исполнителями) — только `.a/handoff/`.
3. **Отчёты** (аудиты, анализы, исследования, скриншоты приёмки) — только `.a/reports/`.

Не создавать агентские файлы в корне репозитория, в `docs/` вместо отчёта агента, в устаревших `.tasks/` / `.handoff/` или в любом другом каталоге.

Исключение: этот `AGENTS.md` остаётся в корне — Grok загружает правила только из известных имён в корне (и не читает файлы из `.gitignore`). `CLAUDE.md` — локальная копия для Claude Code, тоже в корне и тоже в `.gitignore`. Оба файла — указатели на `.a/`, а не рабочие артефакты.

Код, миграции и публичная документация продукта (`README.md`, `docs/DEFECTS.md`, `docs/LIMITATIONS.md`) — не файлы агента; они живут в дереве репозитория как обычно.

## Запрет на использование `tmux capture-pane` (Tmux Stability Rule)
- **Категорически запрещено вызывать команду `tmux capture-pane`**:
  - В установленной версии `tmux` вызов `capture-pane` содержит критический баг повреждения памяти (`malloc_printerr` в `cmd_capture_pane_exec`), вызывающий мгновенное аварийное падение сервера tmux (SIGABRT/coredump).
  - Краш процесса `tmux: server` приводит к аварийному завершению всех сессий tmux пользователя во всех проектах.
  - Для проверки статуса и вывода сервисов всегда используйте чтение файлов логов (`tail`, `cat`), `journalctl`, сетевые проверки (`curl`) или проверку портов (`ss`, `lsof`).
